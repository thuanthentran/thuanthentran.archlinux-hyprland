# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal Arch Linux + Hyprland setup for an ASUS TUF F16 (dual-boot with Windows). Goal: reinstall Arch, clone this repo, run a few commands, get the same desktop back. There is no build or test suite; the "code" is dotfiles, package lists and bash scripts. The repo is public on GitHub.

The machine this is checked out on is the target machine itself, running Hyprland, and the configs are already stowed into `~/.config`. Editing a file under `config/` changes the live desktop immediately (Hyprland reloads its config on save).

## Layout and how the pieces connect

- `config/<component>/.config/<component>/...` — GNU Stow packages. Each top-level dir in `config/` is one stow package whose contents mirror `$HOME`. Link with:
  ```sh
  stow -d config -t ~ <component>      # e.g. hypr, quickshell, rofi, kitty, nwg-dock-hyprland
  stow -d config -t ~ -R <component>   # restow after adding new files
  ```
  `~/.config/hypr` is a real directory (Stow linked its children individually), so a new file or dir added under `config/hypr/.config/hypr/` is not live until you restow `hypr`.
- `packages/*.txt` — one package per line, `#` comments. `base`, `hyprland-desktop`, `apps` and `hardware-<host>` come from the official repos; `aur.txt` from the AUR (via yay). When a config starts depending on a new program, add it to the right list. Find installed packages missing from the lists with `comm -23 <(pacman -Qqe | sort) <(sed -e 's/#.*//' -e '/^\s*$/d' packages/*.txt | sort)`.
- `system/etc/` (all machines) and `hosts/<host>/etc/` (one machine; default host `tuf-f16`) mirror `/etc` and are copied there by `setup.sh system`. The TUF F16 host has udev rules giving the GPUs stable names (`/dev/dri/igpu`, `/dev/dri/dgpu`), which `hyprland.lua` uses for `AQ_DRM_DEVICES`, and a mkinitcpio drop-in removing the `kms` hook for NVIDIA.
- `install/setup.sh` — post-install script, run as the normal user (uses sudo itself), idempotent. Steps: `mirrors packages aur dotfiles system services snapper plugins theme`; run a subset with `bash install/setup.sh dotfiles theme`, preview with `--dry-run`, pick a host with `SETUP_HOST=<name>` (or `none`). `plugins` and `theme` only work inside a Hyprland session. Check after editing: `bash -n install/setup.sh && bash install/setup.sh --dry-run`.
- `install/rank-mirrors.sh` — the `mirrors` step: ranks HTTPS mirrors in nearby countries by downloading part of a real ~100 MB package (not the small db file, which CDNs serve fast from cache even when packages crawl) and writes the top 8 to `/etc/pacman.d/mirrorlist`.
- `install/arch-install.sh` — installs the base system from the Arch live USB (Btrfs subvolumes `@ @home @log @pkg @snapshots`, shares the Windows ESP at `/efi` without formatting, GRUB + os-prober). Supports `--dry-run`; answers can be pre-set through `ARCH_*` env vars listed at the top of the file. It runs as root on the live ISO, so it can't be exercised on this machine beyond `bash -n` / `shellcheck` / reading the dry-run path.
- `install/apply-theme.sh` — called by `setup.sh theme`; applies the macOS-like look (WhiteSur GTK/icons/cursors, IBM Plex Sans UI font, CaskaydiaCove Nerd Font monospace, subpixel font rendering) via `gsettings`; run inside a graphical session. Font rendering for everything else is in `config/fontconfig` (subpixel RGB + hintslight; switch to bgr if text shows colour fringes); kitty has its own `text_composition_strategy`.
- `docs/` — docs in Vietnamese (why Arch, hardware notes, Windows prep, install walkthrough, repo plan, setup + rollback). `docs/05-repo-plan.md` holds default choices and open decisions; `docs/06-setup-and-rollback.md` the post-install checks and the manual snapshot rollback (`snapper rollback` does not work here because the kernel cmdline pins `rootflags=subvol=@`).

## Hyprland config is Lua, not hyprlang

`config/hypr/.config/hypr/hyprland.lua` uses Hyprland's Lua config API (Hyprland 0.57.x): `hl.monitor{}`, `hl.bind(...)`, `hl.dsp.exec_cmd(...)`, `hl.gesture{}`, `hl.exec_cmd(...)`. Dispatchers are also Lua expressions from the shell, e.g. `hyprctl dispatch "hl.dsp.window.cycle_next({ next = true })"`. Don't write classic `hyprland.conf` syntax (`bind = ...`, `exec-once = ...`). Syntax changes between Hyprland releases, so check the wiki for the installed version (`hyprctl version`) before adding options.

Unlike `hyprland.lua`, `hyprlock.conf`, `hypridle.conf` and `hyprpaper.conf` (hyprpaper 0.8 block syntax) still use hyprlang; they are started from the autostart block in `hyprland.lua`, as is `cliphist`. The wallpaper is `wallpapers/default.png` in the same Stow package. The `hyprbars` plugin is built by `hyprpm` and must be rebuilt (`hyprpm update`) after every Hyprland upgrade; its config is wrapped in `pcall` so a missing plugin doesn't break the config.

Window buttons: the `hyprbars` title bar is the only set of min/max/close buttons; app-drawn ones are hidden (`button-layout 'appmenu:'` in `apply-theme.sh` for GTK/Firefox, `window.controlsStyle: hidden` in `config/code` for VS Code). Minimized windows live in `special:magic`; `scripts/minimize.sh minimize|restore` handles it. Moves into a special workspace need `follow = false`, otherwise Hyprland opens the special workspace and the window stays on screen. `scripts/toggle-maximize.sh` resizes floating windows to the work area instead of using Hyprland's maximized state; it restores only when the window fills the work area exactly (position and size), otherwise it maximizes.

Window management follows Windows 11 / macOS, floating-first: every window floats by default (`float-by-default` rule) and tiling is not a goal. The float/tile button was removed from the bar (Super+V still toggles). Windows-11-style snapping (drag to an edge to maximize or snap half / quarter, double-click the title bar, Super+arrows) is deferred, maybe never; snap layouts on hovering the maximize button are out of scope (hyprbars buttons can't host a popup).

Focus is click-to-focus (`follow_mouse = 2`) with `cursor.no_warps`, so keyboard/gesture focus changes don't move the pointer, and `float_switch_override_focus = 0`, since its default sends focus back to the window under the cursor whenever focus crosses between tiled and floating windows (it broke 3-finger cycling). Tiled windows always stay below floating ones, so `bring_to_top` can't raise a tiled window over a floating one. A 150 ms `hl.timer` in `hyprland.lua` (`keep_on_screen`) pushes the active floating window back when its title bar ends up under the top bar or off screen, once the drag has stopped. Don't use `release = true` binds on mouse buttons: they swallow the release even with `non_consuming`, so apps think the button is still held.

Scrolling: Hyprland only scales speed (`scroll_factor` for the mouse and `touchpad.scroll_factor`); inertia is client-side on Wayland, so it is set per app: kitty `momentum_scroll` (touchpad only), VS Code `*.smoothScrolling`, and Firefox prefs in `extras/firefox/user.js` (not a Stow package, since profile dirs have random names; `setup.sh dotfiles` symlinks it into each profile). GTK apps glide on the touchpad by themselves; nothing adds inertia to the mouse wheel system-wide.

Helper scripts live in `config/hypr/.config/hypr/scripts/` and are referenced from the Lua config as `$HOME/.config/hypr/scripts/<name>.sh`, so they must be executable and stowed. Validate after editing:
```sh
hyprctl configerrors        # Lua/config errors in the running session
hyprctl reload
```

The desktop aims to be mouse-friendly and macOS/Ubuntu-like: a top bar written in Quickshell, nwg-dock-hyprland dock, nwg-drawer app grid, rofi as Spotlight (`SUPER+space`), notifications from Quickshell (`Notifs.qml`, which replaced mako), fcitx5-unikey for Vietnamese Telex input, kitty, thunar. The top bar was moved from Waybar to Quickshell (QML) so it can grow stateful widgets (media, system graphs, quick settings that expand in place) Waybar, `nm-applet` and `blueman-applet` were removed once it covered everything (`network-manager-applet` and `blueman` stay installed for `nm-connection-editor` / `blueman-manager`, opened from the bar's drop-downs).

Quickshell: `config/quickshell/.config/quickshell/shell.qml` is the entry point (one `bar/Bar.qml` per screen via `Variants`). Imports go through the `qs` root module: `import qs` for the `Theme.qml` singleton (colours, fonts, bar height) `BarState.qml` (shared state: `expanded` quick settings, `held` sliders) `SysStats.qml` (CPU / RAM / network sampled from `/proc` every second with 60 samples of history, always running), `Backlight.qml` (screen brightness read from sysfs, shared by the bar slider and the OSD), `Players.qml` (the MPRIS player shown: playing one first; pokes `positionChanged()` each second, since MPRIS doesn't push position; Firefox/YouTube only reports length and position part of the time and says 0 in between, so use `Players.length` / `Players.position` / `Players.seek()`, which keep the last real length per track and extrapolate the position, never the player's raw values) `Cava.qml` (12-bar mono spectrum from `cava -p cava.conf` in raw ASCII mode, only while something plays; restarts cava if it exits, so `pkill cava` applies an edited cava.conf) and `Lyrics.qml` (synced lyrics from lrclib.net via XMLHttpRequest, looked up only when the player panel opens, sending just the cleaned title / artist with a generic `Lrclib-Client` header; cached in `Quickshell.cachePath("lyrics.json")` with up to 6 candidates per track, the picked one, a timing offset and the query; the panel steps through candidates, nudges the offset and searches by hand), `import qs.widgets` for shared pieces (`BarButton` = hover pill + tooltip + clicked/wheel signals, its mouse area sits below its children so sliders inside get their own input; `Reveal` = content that slides open when `shown`; `BarSlider` (optional `peak` from `PwNodePeakMonitor` draws a Windows-11-style level meter over the fill; linear, since a dB scale pins mastered music to the end); `DropPopup` = drop-down panel under a bar item (xdg popup grab: closes on an outside click and gets the keyboard; holds the quick settings open; closes when they fold), `MenuRow` / `Switch` / `SectionLabel` / `VolumeRow` for its content; `Sparkline` = Canvas area graph, light style: no box, hairline baseline, smooth thin line, fading fill, dot on the latest value; `Visualizer` = bars from `Cava.values`; `WifiIcon` = Canvas-drawn thin signal arcs (Nerd Font Wi-Fi glyphs look too heavy); `Tooltip`; `Toast`), `import qs.bar` for bar modules. `Notifs.qml` is the notification server (it replaced mako; it must own `org.freedesktop.Notifications`, so no other daemon may run): history until dismissed, popups timed centrally in the singleton (cards are rebuilt when the list changes), Do Not Disturb; `Popups.qml` shows them top right, the clock's `ClockPanel` (calendar + list) lists them; `qs ipc call notifs clear|dnd`. `Osd.qml` (root dir) is the volume / mic / brightness pill near the bottom of the focused screen: it notices PipeWire volume and mute changes itself (not while the quick settings are open), brightness keys in `hyprland.lua` call `qs ipc call osd brightness` since sysfs can't be watched; it has an empty input mask, so clicks pass through. Icons are Nerd Font code points written as `"\u{F057E}"` escapes, not pasted glyphs. `~/.config/quickshell` is a single Stow symlink to the repo dir, so new files are live without restowing, and Quickshell reloads on save, except that a new `.qml` type added to an existing directory may be reported as "is not a type" until a restart, and a file replaced by rename (some editors / tools write that way) can be missed by the watcher: if `qs log` shows no "Reloading configuration", restart; the `//@ pragma IconTheme` line in `shell.qml` only takes effect on a restart (`pkill -x qs; setsid -f qs -d`). It is started as `qs` from the autostart block. Scripts and keybinds talk to it through `IpcHandler`s: `qs ipc show` lists targets, `qs ipc call shell ping` is the smoke test, `qs ipc call bar expand|collapse` opens the quick settings for a screenshot (it folds back only after the mouse has entered and left it), `qs ipc call bar popup sound|wifi|bluetooth|media|clock` opens a drop-down and `collapse` closes them all (without the grab: the compositor refuses a popup grab that isn't caused by a click). Debug with `qs log` and look at the result with `grim -g "0,0 1920x32" out.png`. Available services and their properties can be read from `/usr/lib/qt6/qml/Quickshell/**/*.qmltypes`.

Window overview, Alt+Tab and the 3-finger gesture: `Overview.qml` (root dir) is one full-screen overlay below the bar with three modes. Grid (Super tap, Super+Tab) shows the current workspace's windows, minimized ones in a row below; typing there searches windows and apps (`DesktopEntries`), Esc clears then closes; dragging a tile reorders. Strip (Alt+Tab / Alt+Shift+Tab) puts the picked window in the middle; a quick Alt+Tab switches without showing anything. Film (3-finger swipe, iOS home bar style): sideways moves along the windows (linear, no wrap; the current one zooms out to `zoomTo` while the fingers move level and back to full on release), up shrinks them into a strip and past `gridAt` mm spreads them into the grid, down again gathers them back. Window order is `WindowOrder.qml`, a stable order shared with the bar's taskbar (drag there or in the grid to reorder; new windows at the end); focusing a window doesn't move it. Swipes come from `Touchpad.qml`, which runs `libinput debug-events` on the touchpad (read access from the udev `uaccess` rule in `system/etc/udev/rules.d/`) and reports deltas in mm on the pad; Hyprland's own 3-finger gestures are off (4 fingers still switch workspace). Real windows are never scaled: the overlay paints the wallpaper and `ScreencopyView`s of the windows, each tile drawn at the window's real size and scaled by a transform (resizing it per frame re-rendered the clip and text at rounded sizes and looked choppy), with a drawn stand-in for the hyprbars title bar (screencopy leaves it out); `progress` 0 puts every tile exactly over its window and 1 in the layout, so the windows seem to fly. It stays invisible until the thumbnails have a frame, and a layer rule turns off Hyprland's layer fade for it. Focus is dispatched ~40 ms after closing, since Hyprland ignores focus changes while the overlay holds the keyboard. Keys reach it as GlobalShortcuts (`hl.dsp.global("quickshell:...")`); a `release = true` bind passes `released`, not `pressed`, and a release bind on a modifier (`SUPER + Super_L`) only fires when no other key came in between, so Super tap is safe from Super+T but Alt's release after Alt+Tab is caught by an `hl.timer` polling `hl.is_key_down`, which takes xkb keycodes (Alt_L 64, Alt_R 108). Test without keys or touchpad: `qs ipc call overview toggle|alttab 1|release|swipe begin|move 10 -5|swipe end|search text`; `qs ipc call overview bench` animates it in process for frame timing (with `QT_LOGGING_RULES=qt.scenegraph.time.renderloop=true`). `render.new_render_scheduling` in `hyprland.lua` is on because without it the 144 Hz panel only got frame callbacks at ~72 fps; `debug.overlay` (set live with `hyprctl dispatch '(function() hl.config({...}) end)'`) shows Hyprland's FPS. When editing Quickshell files from the shell, write in place (python, an editor); `sed -i` replaces the file and the watcher misses it.

Bluetooth pairing: Quickshell's Bluetooth module can pair but can't be a BlueZ agent, so `scripts/bt-agent.py` (Gio, started from autostart) registers as the default agent and asks through notifications (passkey confirm with Pair / Cancel actions via `notify-send --wait`, passkeys to type shown, PINs asked with rofi).

Sleep and hibernation: suspend to RAM hangs on the TUF: it goes to sleep (keyboard lights blinking) but never wakes, in s2idle and deep alike, on both kernels, without the Wi-Fi driver and with D3cold off for its port; a timestamp loop proved the kernel itself stops. `pm_test` levels `freezer`/`devices` come back, `platform`/`core` hang, so it dies in the noirq / ACPI stage; pm_trace named `pcieport 0000:00:1c.7` (the Wi-Fi root port), which may just be the last device suspended. Not yet tried: booting without the NVIDIA driver (`module_blacklist=nvidia,...`) and `pcie_port_pm=off`. So nothing suspends: the power menu's Sleep locks and turns the screen off, hypridle hibernates after 30 min instead of suspending, `hosts/tuf-f16/etc/systemd/logind.conf.d/10-no-suspend.conf` makes the lid and sleep key only lock and leaves the power key to Hyprland (short press = screen on), Hyprland turns the screen off on lid close and on with any key / mouse (`misc.key_press_enables_dpms`). `NVreg_EnableS0ixPowerManagement=1` (`hosts/tuf-f16/etc/modprobe.d/nvidia-power.conf`, NVIDIA's advice for s2idle) stays though it didn't help alone. Hibernation uses a RAM-sized swapfile on its own subvolume `@swap` at `/swap` (`setup.sh hibernate`; zram stays first by priority); no `resume=` is needed with a systemd initramfs on UEFI. The bar's power menu shows Hibernate only when logind's `CanHibernate` says yes.

Audio: `config/wireplumber` hides ALSA's "Pro Audio" profile (`api.acp.disable-pro-audio`); without it WirePlumber put the NVIDIA HDMI card on Pro Audio when no screen was plugged in, giving ghost HDMI outputs that once became the default. Restart with `systemctl --user restart wireplumber` after editing.

Hybrid GPU: the session renders on the Intel iGPU; the NVIDIA dGPU (open driver) drives the HDMI port and runs apps via `prime-run`. The laptop has a MUX: `eDP-1` is the panel on Intel, `eDP-2` the same panel on NVIDIA.

## Conventions

- Line endings are forced to LF via `.gitattributes` (the repo was originally edited on Windows). Keep the executable bit on scripts in git (`git update-index --chmod=+x` if needed).
- Machine-specific files go in `hosts/<host>/` and `packages/hardware-<host>.txt`; inside `hyprland.lua` guard them so other machines skip them (see the `/dev/dri/igpu` check).
- There is no passwordless sudo here: write root-level changes into `setup.sh`/`system/`/`hosts/` and let the user run them.
- Never commit secrets (SSH keys, tokens, Wi-Fi passwords).
- Commit messages are short imperative English ("Add Waybar config and autostart"); docs and README are written in Vietnamese.
- README's "Trạng thái" / "Lộ trình" sections track progress and go stale; update them when a milestone lands.
- `TODO.md` is the backlog (Vietnamese, ordered by priority). Tick items (`[x]`) in the same commit that does them, and add new follow-ups there instead of leaving them only in chat.
